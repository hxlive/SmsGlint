# SmsGlint ⚡

> **轻量、灵动的桌面短信验证码接收与自动复制助手**  
> 配合安卓端 [SmsForwarder (短信转发器)](https://github.com/pppscn/SmsForwarder) 使用，通过 MQTT 协议将手机短信秒级投递到电脑桌面，智能提取验证码、灵动气泡弹窗，并支持自动同步至剪贴板。

## ✨ 核心特性

- 🚀 **即时无感投递**：基于 MQTT 协议，支持显式开启 TLS 加密连接；只要手机转发端和电脑均能访问 MQTT 服务，就不要求处于同一 WiFi。
- 🎨 **灵动滑入气泡**：右下角紧凑悬浮卡片平滑滑入，8 秒无操作自动滑出；适配 **4K / 高 DPI 缩放**（125%、150%、200% 等），不遮挡任务栏。
- 🔔 **新消息托盘闪烁**：收到新验证码时，系统托盘图标**呼吸闪烁提醒**（点击气泡或托盘菜单自动复原，或 4 秒后自动停留在常驻状态）。
- 🔊 **轻量提示音**：支持收到验证码时播放系统内置轻柔提示音（Windows / macOS 原生支持，0 体积增加，可一键开启/关闭）。
- 📋 **可选自动复制**：支持自动写入系统剪贴板，收到验证码后可直接粘贴；亦可在配置中关闭，仅保留弹窗提醒。
- 📌 **托盘快捷复制**：托盘菜单提示“最新验证码已收到”，但不明文展示验证码；错过弹窗或剪贴板被覆盖时仍可一键重新复制。
- ⚡ **开机自动启动**：图形化界面提供一键开机自启开关，原生兼顾 Windows（注册表）与 macOS（LaunchAgents plist）。
- 🔍 **智能精准提取**：支持 **4 ~ 6 位** 动态验证码识别，针对包含多个数字的短信自动进行语义上下文分析（关键词优先匹配），避免误提取手机号或快递单号。
- 🏷️ **短信平台识别**：自动提取短信中的 `【平台名称】`，让用户一眼确认验证码来自哪个平台。
- 🛠️ **完整 GUI 配置**：首次启动自动引导配置；已有有效配置时自动验证，连接与订阅正常则不重复弹窗。
- 🔄 **事件驱动断线自愈**：MQTT 底层使用指数退避自动重连，同时托盘支持手动一键重连。
- 📦 **单文件部署**：源码保持单文件结构，并提供 PyInstaller spec；当前 `v1.2.0` 尚未重新编译 EXE。
- 🔒 **单实例保护**：内置进程互斥锁，防止多开造成消息重复消费或冲突。
- 🛡️ **输入与隐私保护**：限制 MQTT 载荷及字段长度；日志不保存验证码和完整短信正文。

## 🏗️ 工作原理

```text
  [📱 安卓手机 (收到短信)]
            │
            ▼ (提取短信内容)
   [SmsForwarder 短信转发器]
            │
            ▼ (Webhook API / MQTT 客户端推送)
  [☁️ EMQX Serverless MQTT 服务端 (免费免运维)]
            │
            ▼ (TLS 8883 加密订阅推送)
   [💻 PC 桌面: SmsGlint]
            │
    ┌────────────┼─────────────────┐
    ▼            ▼                 ▼
[🏷️ 识别平台] [🎯 提取验证码]  [📋 同步剪贴板 (可选)]
    └────────────┬─────────────────┘
                 ▼
      [🎨 右下角滑入气泡 (8秒自动关闭)]
```

## 🚀 快速上手

### 方式一：直接运行独立 EXE（推荐）
1. 从项目 Release 获取已发布的 SmsGlint EX。
2. 双击运行即可。首次运行会自动弹出配置窗口，填写 MQTT 连接信息并保存。
3. 托盘图标将常驻在右下角任务栏。

### 方式二：Python 源码运行
1. 克隆或下载本项目源码。
2. 运行环境要求：`Python 3.10+`。
3. 在终端进入项目目录并执行：
   ```bash
   python SmsGlint.py
   ```
   > 项目会检测缺少的依赖（`customtkinter`、`paho-mqtt`、`pystray`、`pyperclip`、`Pillow`），列出组件并询问是否安装；只有用户确认后才会联网调用 pip。

4. 如需在不配置 MQTT 的情况下查看弹窗：
   ```bash
   python SmsGlint.py --preview
   ```
   预览不会自动关闭，点击卡片或按 `Esc` 退出。

## ⚙️ 服务端与安卓端配置指引

### 1. 准备 MQTT 服务端
可以使用自建 MQTT Broker，或使用 **[EMQX Cloud](https://cloud.emqx.com/)** 等托管服务。不同服务的套餐、额度和端口可能调整，请以服务商当前控制台为准：
1. 注册并创建一个 MQTT 部署。
2. 在控制台的【认证鉴权】中添加一个客户端用户名和密码。
3. 获取连接地址（Host）、端口和 TLS 要求。常见 TLS 端口为 `8883`，普通端口为 `1883`，但最终以服务端配置为准。

---

### 2. 安卓手机端配置 (SmsForwarder)
在安卓手机上安装 **[SmsForwarder](https://github.com/pppscn/SmsForwarder)**：

#### ① 添加发送通道（推荐 Webhook 或 MQTT）
以 **Webhook** 方式推送到 EMQX HTTP 接口（或直接使用 MQTT 客户端通道）为例：
- **通道类型**：`Webhook` 或 `MQTT`
- **Topic (主题)**：`sms/verify_code`（需与 SmsGlint 中设置的主题一致）
- **推送数据格式**（JSON 格式）：
  ```json
  {
    "device_id": "[extra_device_mark]",
    "sender": "[from]",
    "content": "[msg]"
  }
  ```

#### ② 添加转发规则
- **规则类型**：短信
- **匹配模式**：全部匹配 或 包含关键词（如“验证码”、“校验码”、“code”等）
- **发送通道**：勾选上一步创建的通道

---

### 3. PC 端 (SmsGlint) 配置

首次启动程序会自动弹出配置界面（或随时右键系统托盘图标 -> **MQTT 配置**）：

| 配置项 | 说明 | 示例 / 默认值 |
| :--- | :--- | :--- |
| **服务器地址 (Host)** | EMQX 提供的集群连接地址 | `xxxxxx.emqxsl.cn` |
| **端口** | 默认 TLS 加密端口为 8883，普通为 1883 | `8883` |
| **用户名** | MQTT 鉴权用户名 | `your_username` |
| **密码** | MQTT 鉴权密码 | `your_password` |
| **订阅主题 (Topic)** | 接收短信的主题（需与手机端一致） | `sms/verify_code` |
| **启用 TLS 加密连接** | 使用系统证书信任库建立 TLS 连接 | `开启 (8883 推荐)` |
| **自动复制验证码** | 收到验证码时自动写入剪贴板（可选开关） | `开启 (默认)` |
| **收到时播放提示音** | 收到验证码时触发系统原生轻音效（可选开关） | `开启 (默认)` |
| **开机自动启动** | 开机随系统静默后台启动（Win/Mac 自适应） | `关闭 (默认)` |

点击 **【测试连接】**。程序只有在 MQTT 连接成功并收到主题订阅确认（SUBACK）后才会提示成功；随后点击 **【保存】** 即可。

## 📝 配置文件说明

SmsGlint 会在程序同级目录下自动维护 `config.json` 配置文件：

```json
{
  "host": "xxxxxx.emqxsl.cn",
  "port": 8883,
  "username": "your_username",
  "password": "your_password",
  "topic": "sms/verify_code",
  "use_tls": true,
  "auto_copy": true,
  "play_sound": true
}
```

- `host` 和 `topic` 不能为空，端口必须处于 `1～65535`。
- 旧配置没有 `use_tls` 时，端口 8883 默认启用 TLS，其他端口默认关闭。
- 配置采用临时文件写入和原子替换，降低写入中断造成 JSON 损坏的风险。

> `config.json` 当前仍以明文保存 MQTT 密码。请限制文件访问权限，不要提交到公开仓库或发送给他人。

## 💡 托盘菜单功能

右键系统托盘图标可使用以下功能：
- **最新验证码**：提示最近验证码已收到，但不明文展示内容；点击即可重新复制到剪贴板。
- **重新连接**：手动触发 MQTT 快速回连。
- **MQTT 配置**：打开图形化设置窗口修改连接参数、自动复制、提示音与自启动设置。
- **查看日志**：打开实时运行日志窗口，查看消息接收与连接状态。
- **退出**：安全退出并释放后台资源。

## 🔐 隐私与安全

- MQTT TLS 使用系统默认安全上下文和系统证书信任库，不固定到已弃用的协议版本。
- 单条 MQTT 载荷最大 64 KiB；设备和发送方字段最大 128 个字符；短信正文最大 16 KiB。
- JSON 顶层、字段类型、编码或长度无效时拒绝处理，并在日志中记录原因。
- 运行日志不保存验证码，也不保存完整短信正文。
- 源码缺少依赖时必须由用户确认；pip 使用参数数组，不经过 Shell，并禁止交互和源码包构建。
- MQTT 工作线程只向线程安全队列写入事件，由 Tk 主线程更新界面。
- 配置窗口、剪贴板、提示音及开机启动失败时会显示或记录具体原因，减少静默失败。

## ❓ 常见问题 (FAQ)

<details>
<summary><b>Q1: 如何设置开机自启动？</b></summary>
打开 SmsGlint 的“MQTT 配置”窗口，勾选“开机自动启动”并保存。Windows 使用当前用户注册表 <code>CurrentVersion\Run</code>，macOS 使用 <code>LaunchAgents</code> plist；无需手动复制快捷方式。
</details>

<details>
<summary><b>Q2: 为什么有时短信里有多个数字能精准提取到验证码？</b></summary>
SmsGlint 采用了双重匹配策略：首先扫描所有 4~6 位的独立数字；当短信中包含多个数字时，结合“验证码 / 校验码 / code / 是 / 为”等前后上下文关键词进行加权识别，确保提取准确。
</details>

<details>
<summary><b>Q3: 关闭【自动复制验证码到剪切板】后如何使用？</b></summary>
当您关闭该选项时，收到短信只会弹出气泡提醒，不会覆盖您当前的剪贴板内容。如果此时需要复制，只需鼠标点击弹出的气泡卡片，即可主动复制并关闭卡片。
</details>
